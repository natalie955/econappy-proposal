Engagement Philosophy

Teaching by Building

We design every workflow, integration and safeguard with you in working sessions. Nothing gets handed over as a finished black box. By the end of the engagement, the Eco Nappy team should be able to:

  • Read any business function and work out where automation belongs, and where it doesn’t
  • Design a workflow on a whiteboard before touching a tool
  • Choose a stack based on how the data flows, not on hype
  • Know what an AI agent can safely be trusted with, and what it can’t
  • Build in guardrails by default: human checkpoints and audit trails from the start
  • Apply the same method to a different founder’s business afterwards
Guiding Principle

Automate the movement of the right information to the right person at the right time. Nothing gets automated just because it can be.

Every automation we propose has to answer one question: what commercial decision does this speed up or improve? If it has no answer, it doesn’t get built.

Phase 0 · Weeks 1–2

Business Architecture Audit

Before we automate anything, we map how the business actually runs today. This phase is for diagnosis, not building, and everything that follows depends on it.

  • System inventory workshop

    A list of every tool in use: Shopify, Takealot, Meta Ads, Google Ads, Xero, banking, fulfilment and logistics, Google Drive or OneDrive, spreadsheets, and how the team currently uses ChatGPT and Claude.

  • Data inventory

    For each system: what data lives there, who owns it, how it gets in and how it gets out.

  • Process shadowing & interviews

    We walk through a real order, a real ad campaign, a real supplier reorder, a real customer query and a real month-end close.

  • Bottleneck mapping

    Where information gets stuck, retyped or lost between systems.

  • Decision-point mapping

    Which commercial decisions get made weekly and monthly, and what information should feed each one automatically but doesn’t today.

The CRM Question

Do you actually need a CRM?

We don’t assume you do. The audit gives you an honest answer, based on the data map rather than a preference for any product.

The options on the table:

  • A central CRM or hub that everything reports into
  • A lighter connective layer: a data warehouse plus an automation layer
  • One system of record with the others feeding into it

We come back to this question in the Stack step, once the real data flows are mapped. It isn’t a purchase we make in week three.

Deliverable: Business Architecture Map

Safeguards Framework

Every Automation Is
Classified Before It Ships

This applies to every function. Before any automation or AI agent goes live, we agree how much it can do without a person involved.

Tier 1

Autonomous

Safe to run without anyone reviewing it.

For exampleA dashboard refresh, an internal alert
Tier 2

Human-approved

AI drafts it, and a person approves it before it goes out.

For exampleCustomer-facing replies, financial reports, ad budget changes
Tier 3

Human-only, AI-assisted

AI provides the analysis and options. A person makes and carries out the decision.

For examplePricing changes, supplier negotiations, hiring
And for every workflow

Whatever its tier, each workflow is documented with four answers before deployment.

Failure mode

What happens if the automation is wrong or the integration breaks?

Audit trail

Where is the log of what the system did, so it can be checked?

Kill switch

How can Eco Nappy, or the team, switch it off instantly if something looks wrong?

Data access boundaries

What each agent or tool can see, and what is explicitly off limits, such as financial credentials and customer personal information.

Stack Decision Principles

No Tools Chosen Upfront

We don’t prescribe tools at the start. Each Stack step is decided against the same five criteria.

  1. Does an existing tool already do this well enough?

    The first job is to avoid adding more tools than the business needs.

  2. Connection problem, or missing capability?

    If there’s a gap, is it because two systems don’t talk to each other (an integration layer fixes that), or because the capability doesn’t exist yet (a new tool fixes that)?

  3. Build vs. buy vs. connect

    A lightweight automation platform such as Make or Zapier, a native integration, or a custom AI agent. Whichever fits the job.

  4. Total cost of ownership

    Who maintains this once we leave: Eco Nappy, the team, or does it need to be simple enough that nobody has to?

  5. Reversibility

    Can it be undone or swapped out without breaking the rest of the system?
